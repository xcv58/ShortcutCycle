它解决什么问题

不是再做一个全能启动器，而是把几组高频 App 的切换路径固定下来。

Command+Tab 太线性

当同时开很多 App 时，Command+Tab 会变成一条很长的历史列表。每次都要扫图标、数位置、或者多按几次。

按场景切换

把常用 App 分成 Web / Code / Chat / Writing 等组。比如 Option+1 只在浏览器组里循环，Option+2 只在开发工具里循环。

靠肌肉记忆

不搜索、不输入、不看全局窗口列表。你的手指知道「Code 组」在哪里，按一下就切过去，再按就在组内循环。

先说清楚：它不是什么

如果你的工作流已经被别的工具完整解决了，ShortcutCycle 可能不需要加入。

  • 它不是窗口级切换器。如果你需要所有窗口缩略图和精确选窗口，AltTab / Contexts 可能更适合。
  • 它不是 Raycast / Alfred 替代品。ShortcutCycle 不解决搜索和命令启动的问题。
  • 它更像是一个很小的补充：给几组高频 App 固定快捷键，用肌肉记忆快速循环。

FAQ

和 AltTab 有什么区别？

AltTab 更适合窗口级切换：看所有窗口，再选一个。ShortcutCycle 解决的是另一个小场景：你已经知道要去 Web / Code / Chat 这一组，只想用固定快捷键在这组 App 里循环。

为什么不做窗口级切换？

ShortcutCycle 目前专注 App 级切换。窗口级切换通常需要更深入的辅助功能权限和更复杂的窗口控制。这个项目更偏向轻量、稳定、少权限。

兑换码用户可以给 App Store 评价吗？

不可以。所以这次不是求 review，主要是想换真实试用反馈。

我可以自己编译吗？

可以。ShortcutCycle 是开源项目。如果你习惯自己编译，也可以直接从 GitHub 构建。App Store 版本主要适合想要即装即用和自动更新的人。

兑换码一定会发吗？

不一定。数量有限，我会优先发给有具体使用场景、愿意反馈的 V 友。

愿意帮我验证这个想法吗？

如果你每天都在几个固定 App 之间来回切，欢迎申请试用。最有价值的反馈不是“好用”，而是：这个模型在哪些场景不成立、哪里不直觉、默认分组应该怎么改。
